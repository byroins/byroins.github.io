网络通讯协议—DHCP-DNS

Posted on 2026-04-04 Edited on 2026-10-15 In network , DHCP-DNS Views:

1.0 DHCP

一台主机接入网络后要能正常通信，至少需要四样参数：IP 地址、子网掩码、默认网关、DNS 服务器地址。几台机器手工配置没有问题，几十上百台机器的网络里无法维护，换一个网段就要全部重配一遍。DHCP（Dynamic Host Configuration Protocol，动态主机配置协议）把这四样参数连同租期一起自动下发。

DHCP 工作在应用层，基于 UDP：服务端使用 67 端口，客户端使用 68 端口。协议由 BOOTP 扩展而来，因此在抓包工具里过滤 DHCP 报文要使用 bootp 过滤器而不是 dhcp。

1.1 报文格式

DHCP 报文分成两段：固定长度的头部，以及可变长的选项字段。

字段 长度 说明
OP 1字节 报文类型，1 = 请求，2 = 应答
HTYPE 1字节 硬件类型，以太网为 1
HLEN 1字节 硬件地址长度，以太网 MAC 为 6
HOPS 1字节 经过的 DHCP 中继跳数，客户端置 0，每经过一个中继加 1，用来防止环回
XID 4字节 事务 ID，客户端随机生成，用来把请求与应答配对
SECS 2字节 客户端从开始申请到此刻经过的秒数
FLAGS 2字节 最高位置 1 表示要求服务端以广播方式应答
CIADDR 4字节 客户端已有的 IP 地址，首次申请时为 0.0.0.0
YIADDR 4字节 服务端分配给客户端的 IP 地址
SIADDR 4字节 下一个为客户端提供服务的服务器地址
GIADDR 4字节 中继代理的地址，跨网段时由中继填入
CHADDR 16字节 客户端硬件地址，即网卡 MAC
SNAME 64字节 服务器名称，可选
FILE 128字节 启动文件名，无盘工作站网卡启动时使用
Options 可变 以魔术字 0x63825363 开始，所有实际参数都在这里

头部只规定了地址填在哪一格，真正决定下发什么参数的是 Options。

选项码 名称 说明
53 DHCP Message Type 报文类型，决定这条报文是 DISCOVER / OFFER / REQUEST / ACK 中的哪一种
50 Requested IP Address 客户端希望申请的地址
54 Server Identifier 客户端选中的服务器地址
51 IP Address Lease Time 租期
58 Renewal (T1) Time 续约时间点
59 Rebinding (T2) Time 重绑时间点
1 Subnet Mask 子网掩码
3 Router 默认网关，可以下发多个
6 Domain Name Server DNS 服务器地址
15 Domain Name 域名，用于把无后缀的主机名补全

1.2 交互过程

首次获取地址要交换四条报文，取首字母简称 DORA。

除了这四条，还有三种报文。

报文 Options 53 方向 触发场景
DHCP NAK 6 服务端 → 客户端 拒绝 REQUEST，例如申请的地址不在地址池内，或已经租给别的客户端。客户端收到后重新从 DISCOVER 开始
DHCP DECLINE 4 客户端 → 服务端 免费 ARP 检测到地址冲突，告知服务器这个地址不能用
DHCP RELEASE 7 客户端 → 服务端 客户端主动放弃地址，提前归还给地址池

DISCOVER 和 REQUEST 都用广播，原因是一致的：在拿到 ACK 之前，客户端并不知道自己会被分配哪个地址，也就无法用目的 IP 寻址，只能依赖二层广播送出，由网段内的主机接收后，再交给运行 DHCP 服务的进程判断是否处理。

引申：DHCP 协议本身没有任何认证机制，网段内任何一台主机都可以起一个 DHCP 服务并应答 DISCOVER。伪造的服务器只要抢先应答，就能把自己的地址作为网关和 DNS 下发，客户端之后的所有流量都先经过攻击者。为了确保抢到应答，攻击者通常先做 DHCP 饿死攻击（DHCP Starvation），用伪造源 MAC 的大量 DISCOVER 报文把真实服务器的地址池耗尽，此时伪造服务器就成了唯一应答方。企业网络里对应的防护是交换机端口的 DHCP Snooping，只信任连接合法服务器的那个端口。

1.3 租期与续约

DHCP 分配的是租期，不是永久占用。主机下线后如果地址一直被占着，地址池很快会不够用。

1.4 DHCP 中继

路由器不转发广播报文，而 DISCOVER 就是广播，因此 DHCP 服务器与客户端必须处在同一个广播域内。一栋楼有几十个网段，如果每一段都部署一台 DHCP 服务器，维护成本无法接受。

DHCP 中继（Relay Agent）用来解决这个问题：网关设备在本地网段接收客户端的广播，转成单播发给远端 DHCP 服务器，同时把收到广播的那个接口地址写进 GIADDR 字段。服务器依据 GIADDR 判断客户端属于哪个网段，从对应的地址池里取地址。

1.5 抓包观察

观察重点是 Options 53 的取值如何依次变化，以及 YIADDR 在哪一条报文里被填上。DISCOVER 的 XID 与后续三条完全一致，这是把它们串成一次完整交互的依据。

2.0 DNS

DHCP 下发的参数里有 DNS 服务器地址，因为人记不住 IP。DNS（Domain Name System，域名系统）负责把域名与地址对应起来。

2.1 域名结构

域名是一棵树，从右往左逐级细化，各级之间用点分隔，最右边是通常省略的根。

  • 根域用单个点表示，写作 .
  • 顶级域分两类：通用顶级域 gTLD（com、net、org、edu）和国家地区顶级域 ccTLD（cn、jp、uk）
  • 每一级标签不超过 63 字节，完整域名不超过 253 字节
  • 域名不区分大小写
  • 写成 www.example.com. 时末尾那个点表示根，这种写法叫 FQDN（完全限定域名），配置文件里要求写全

2.2 查询过程

DNS 查询分两种，区别在于谁去跑腿。

  • 递归查询：客户端向本地 DNS 服务器发出一次请求，服务器必须返回最终结果，不允许只回一句”下一步该问谁”
  • 迭代查询：本地 DNS 服务器向根、顶级域、权威服务器逐级询问，每一级返回的是”下一步该问谁”

从在浏览器里敲下一个域名到真正发出请求，中间还会经过几层缓存和本地配置，全都未命中才会走到上面的迭代查询：

  • hosts 文件里的静态映射不经过网络，本地 DNS 服务器也无法覆盖它。Linux 在 /etc/hosts，Windows 在 C:\Windows\System32\drivers\etc\hosts
  • Linux 上本地 DNS 服务器的地址写在 /etc/resolv.conf，Windows 上执行 ipconfig /all 查看
  • 查询与应答默认走 UDP 53。应答长度超过 512 字节时会被截断（Flags 中 TC 位置 1），客户端改用 TCP 53 重新发送；区域传送（AXFR）和 DNSSEC 也必须使用 TCP

2.3 报文格式

DNS 只有一种报文格式，靠 Flags 里的 QR 位区分查询和应答。

头部长度固定 12 字节。

字段 长度 说明
ID 2字节 事务 ID，用来把查询与应答配对
Flags 2字节 标志位，见下表
QDCOUNT 2字节 问题段记录数
ANCOUNT 2字节 回答段记录数
NSCOUNT 2字节 权威段记录数
ARCOUNT 2字节 附加段记录数

Flags 字段的各位：

位 名称 说明
QR 查询/应答 0 = 查询，1 = 应答
Opcode 操作码 0 = 标准查询，5 = 动态更新
AA 权威回答 该应答来自本域的权威服务器
TC 截断 应答超过 512 字节被截断，需要用 TCP 重发
RD 期望递归 客户端置 1，要求服务器完成递归查询
RA 递归可用 服务器置 1，表示自己支持递归
RCODE 返回码 0 = 成功，3 = 域名不存在（NXDOMAIN），5 = 拒绝

头部之后是四段，顺序固定：问题段（Question）、回答段（Answer）、权威段（Authority）、附加段（Additional）。问题段里是要查的名字加查询类型，回答段里是一条条资源记录，权威段在没有答案时用来指出谁才是权威，附加段携带 NS 与 MX 记录所指向主机的地址，省掉一次额外查询。

2.4 资源记录类型

类型 用途 示例
A 域名到 IPv4 地址，最常用 www.example.com. 300 IN A 203.0.113.10
AAAA 域名到 IPv6 地址 www.example.com. 300 IN AAAA 2001:db8::10
CNAME 别名，把域名指向另一个域名 blog.example.com. 300 IN CNAME www.example.com.
MX 邮件交换记录，带优先级数字，数字越小越优先 example.com. 3600 IN MX 10 mail.example.com.
NS 该域的权威 DNS 服务器 example.com. 3600 IN NS ns1.example.com.
PTR 反向解析，由 IP 查域名，记录写在 in-addr.arpa 域下 10.113.0.203.in-addr.arpa. 300 IN PTR www.example.com.
SOA 区域起始授权记录，描述区域的权威、序列号和各时间参数，每个区域有且只有一条 通常与 NS 记录一同返回
TXT 文本记录，常用于 SPF、DKIM 和域名所有权验证 example.com. 300 IN TXT "v=spf1 include:..."
SRV 服务定位，标明服务所在主机与端口 _sip._tcp.example.com. 300 IN SRV 10 5 5060 sip.example.com.
CAA 指定允许为该域签发证书的 CA example.com. 300 IN CAA 0 issue "letsencrypt.org"

引申：DNS 记录本身就是一份资产清单。NS 记录指出权威服务器，MX 记录指出邮件服务，TXT 记录里往往写着第三方服务的域名，CNAME 会暴露业务用了哪家的对象存储或 CDN。子域名爆破、证书透明日志查询，目的都是把这份清单补全。区域传送如果被错误放行，一次 AXFR 请求就能拿到整份记录。

2.5 缓存与 TTL

资源记录里的那个数字就是 TTL。

  • TTL 由该域名的权威服务器设定，本地 DNS 服务器和操作系统都按它缓存，缓存期内不再发起查询
  • TTL 取小了（例如 60 秒），记录变更后生效快，代价是查询量上升；取大了（例如 86400 秒），查询量小，改完要等很久才全网生效
  • 查不到的域名也会被缓存。NXDOMAIN 的负缓存时长由 SOA 记录里的 minimum 字段决定
  • 改动本机 hosts 文件立即生效，但浏览器可能还有自己的一层缓存

2.6 查询工具

dig +trace 的输出就是 2.2 节迭代查询流程的实际展开，逐级看到的 NS 记录就是那句”下一步该问谁”；dig 返回头部里的 flags: qr rd ra 正好对应 2.3 节 Flags 字段的各位。

引申：DNS 在渗透里还有一个方向是流量控制。DNS 查询几乎不会被出口防火墙拦下，把数据编码进查询名再发出去，就是一种能绕过访问管控的出网通道，也就是 DNS 隧道。反过来的方向是篡改，客户端拿到伪造的解析结果后就会连到攻击者的服务器上，这也是内网里伪造 DNS 服务器比伪造网关更隐蔽的原因。
